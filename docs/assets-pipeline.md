# 素材管线

素材管线负责把素材在可读工程文件与客户端运行时二进制之间互相转换。管线代码与格式结论在 `single-branch/assets` 仓库, 客户端只消费管线产物。

## 一、基本原则

| 原则 | 说明 |
|:---:|:---:|
| 工程文件可读 | 素材以可直接编辑的工程文件形态保存, 文本为 UTF-8 无 BOM 且 LF 换行 |
| 客户端只消费生成物 | 客户端不读取工程文件, 也不实现原版的解密加载链 |
| 资源不加密 | 运行期资源以明文容器随安装包下发 (R11) |
| 命名自写 | 文件名, 目录名, 物品名与代码标识符一律自写, 对照关系只留在映射表 (R18) |
| 双向可校验 | 管线必须能把工程文件重新编码回原始容器, 并用摘要证明未丢失信息 |

## 二、仓库分工

| 仓库 | 职责 | 输入 | 输出 |
|:---:|:---:|:---:|:---:|
| assets | 编解码工具, 格式结论, 清点与校验报告 | 原版运行时二进制 | 可读工程文件与运行时二进制 |
| client | 运行时资源子集与安装包打包脚本 | 管线生成的二进制 | 安装包内资源 |
| server | 不参与素材流转 | 无 | 无 |

解码产物与编码产物都按需重建, 不纳入版本管理; 进入版本库的是工具代码, 格式文档, 契约测试与清点报告。

## 三、数据流

```
原版运行时二进制 (加密容器或自定义容器)
        │
        │  forge unpack       解码, 逐文件登记索引
        ▼
可读工程文件 (人工编辑与工具批量改写的权威数据)
        │
        ├──── forge pack --target plain       确定性明文, 交给客户端
        │
        └──── forge pack --target original    重新套回原容器, 用于逐字节校验
        │
        ▼
运行时二进制 ── 按命名映射表改名 ──> client/src/assets ── 构建期打包 ──> APK
```

客户端侧还有两个打包脚本: `build_atlas.py` 把方块贴图合成为图集, `pack_assets.py` 把音频等资源复制进安装包资源目录。两者的产物都不纳入版本管理, 构建前重新生成。

## 四、管线命令

| 命令 | 作用 |
|:---:|:---:|
| `python -m forge.cli formats` | 列出已登记的编解码器与保真级别 |
| `python -m forge.cli census` | 全量清点素材, 产出 CSV 报告 |
| `python -m forge.cli unpack` | 解码素材到工程树, 并写索引 |
| `python -m forge.cli pack` | 由工程树编码出二进制, 默认目标为明文 |
| `python -m forge.cli pack --target original` | 编码回原版容器, 用于逐字节校验 |
| `python -m forge.cli verify` | 校验索引与工程文件完整性 |
| `python -m unittest discover -s tests` | 运行编解码器契约测试 |

## 五、编解码器与容器结论

| 容器或格式 | 魔数 | 编解码器 | 保真级别 | 说明 |
|:---:|:---:|:---:|:---:|:---:|
| 文本族容器 | `ffd9ffd7` | `container-text-xor16-zlib` | lossless-edit | 包住 Lua, CSV 与 XML; 解出文本后可直接编辑, 再编码可逐字节还原 |
| 二进制族容器 | `ffd9ffd8` | `container-binary-xor16-head` | lossless-passthrough | 包住 KTX, Ogg 与自定义模型容器; 载荷层自动下钻 |
| KTX 11 纹理 | `ab4b5458` | `ktx11` | lossless-passthrough | 头部字段已出视图, 像素待解 |
| 命名区块容器 | `89674523` | `named-block` | lossless-passthrough | 块名已出视图, 块边界与字段待切分 |
| 明文文本 | 无 | `plain-text` | lossless-edit | 按扩展名识别, 文本直接编辑 |
| 公开格式 | 各自魔数 | `png` `gif` `jpeg` `zip` `ttf` `ogg` `mp3` `webp` | lossless-passthrough | 只出结构视图, 载荷原样保存 |
| Android 二进制 XML | `03000800` | `axml` | lossless-passthrough | 输出可读视图与资源引用 |
| 兜底 | 无 | `opaque` | lossless-passthrough | 未解格式原样保留并记录摘要, 管线不跳过文件 |

以下格式尚未接入, 目前在管线上以兜底编解码器保留: VMOF 体素模型 (`564d4f46`), CUST 自定义模型 (`43555354`), 世界区块 (`0c1c0706`)。

## 六、管线契约

| 契约 | 内容 |
|:---:|:---:|
| 逐字节往返 | `encode(decode(x)) == x`, 解码不丢信息, 编码是解码的严格逆运算 |
| 明文确定性 | 同一份工程文件多次编码得到同一份字节, 便于版本管理与差异比对 |
| 索引唯一权威 | 编码参数, 原始编码, BOM, 换行与源摘要全部记录在索引文件里, 不存在只存在内存中的隐式状态 |
| 保真级别 | `lossless-edit` 表示工程文件是权威数据且可编辑; `lossless-passthrough` 表示工程文件保存原始载荷并附可读视图 |
| 不丢素材 | 任何未解格式都原样保留并记录摘要 |
| 职责单一 | 编解码器不读写索引与工程树, 文件系统操作集中在工程树模块 |

## 七、命名与映射

映射表为 `client/src/shared/naming/resource-map.tsv`, 三列: 原相对路径, 新相对路径, 字节数。当前登记 23541 条素材, 是原版与项目命名的唯一对照来源。

改名处理顺序:

1. Unicode NFKC 归一
2. 品牌词替换, 大小写不敏感
3. 全部转小写
4. 空格与特殊字符转为下划线
5. 合并连续下划线并去掉首尾下划线
6. 拆分扩展名, 扩展名保留并小写, 不参与品牌词替换
7. 同目录重名时先到者保留原名, 后来者追加序号

| 原版词 | 替换结果 | 语义 |
|:---:|:---:|:---:|
| `minicoin` | `mirror_shard` | 货币 |
| `minihomecoin` | `home_shard` | 家园币 |
| `miniworks` | `workshop` | 工坊 |
| `mini` 独立词 | `immirror` | 品牌词改为本项目名 |
| 迷你 | `immirror` | 中文品牌词 |

映射表变更后需同步重新生成产物, 不允许在代码里零散硬编码原版名称。

## 八、客户端侧消费

| 资源 | 客户端位置 | 用途 |
|:---:|:---:|:---:|
| 方块贴图 18 个 PNG | `src/assets/blocks` | 图集合成来源 |
| 交互音效 6 个 Ogg | `src/assets/sounds` | 破坏与放置音效, 由 SoundPool 播放 |
| 登录背景 1 个 JPEG | `src/assets/ui` | 账号界面背景 |

| 脚本 | 输入 | 产物 |
|:---:|:---:|:---:|
| `build_atlas.py` | `src/assets/blocks` 下的贴图 | 1024x1024 的 RGBA8 图集与格位表, 16x16 格, 每格 64 像素 |
| `pack_assets.py` | `src/assets` 下清单登记的音频 | 安装包资源目录内的同名文件 |

图集格位顺序必须与原生侧方块注册表的面索引一致, 新增方块时两边同步修改。Gradle 侧对 `ogg` `ktx` `png` `json` 关闭压缩, 以便用文件描述符直接打开。

## 九、新增一种格式

1. 在 `forge/codecs` 下新增模块并继承编解码器基类
2. 声明名称, 保真级别, 可读性分级, 扩展名与魔数
3. 实现解码, 文本类给出文本与编码参数, 二进制类给出原始载荷
4. 需要可读视图时实现视图函数, 返回可序列化的字典
5. 在注册表登记, 魔数路线优先于扩展名路线
6. 在契约测试里补合成样本与真实样本的往返用例
7. 在格式文档补充该容器的结论与推进状态

## 十、校验门禁

| 门禁 | 判定 |
|:---:|:---:|
| 全量解码 | `unpack` 遍历整棵树且不跳过文件 |
| 逐字节还原 | `pack --target original` 与索引中的源摘要逐文件一致 |
| 明文确定性 | `pack --target plain` 连续两次产出的字节完全一致 |
| 契约测试 | 合成样本与真实样本往返通过; 真实样本缺失时用例自动跳过 |
| 客户端侧 | 构建前重新生成图集与音频副本, 缺失时构建立即失败 |

上述门禁全部通过才允许把编解码器合入素材仓库。
