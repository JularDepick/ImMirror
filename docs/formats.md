## 二、结构容器

### KTX 11 纹理 `AB 4B 54 58 20 31 31 BB`

| 项 | 值 |
|:---:|:---|
| 结构 | 标准 KTX 11, 64 字节头加 mip 链, 内部格式以 glInternalFormat 为准 |
| 载荷 | 4368 个明文纹理全部为 ETC1_RGB8 (0x8D64), 4x4 块 8 字节 |
| 当前 | 头部字段出视图, 0 级像素解出 PNG 旁挂文件 (`_png/<rel>.png`); 已有 PNG 回写与自检命令 |
| 回写 | 像素未改时原样回写; 像素改动后重压块并重算 mip 链, 与源文件不逐字节相同 (有损重编码) |
| 推进点 | 逐字节回写需要保留原始压缩块; ETC2 与 PVRTC 的编码路径未做 |
| 关联线索 | 引擎另有 33 字节自定义纹理头, 摘要为 `MD5("miniw20150320\x00" + 正文 + "\x00")`,
可用于校验回写结果 |

### 命名区块容器 `89 67 45 23`

| 项 | 值 |
|:---:|:---|
| 结构 | 魔数加版本加恒为 1 的字段, 其后为具名区块序列, 区块无长度字段 |
| 覆盖 | `.emo` `.ent` `.omod` `.otex` `.oanim` |
| 已解 | 20 个块名的长度闭式 (逆向口径覆盖 50634/50672), 本项目实测 86861/86890 即 99.97% |
| 当前 | 块边界按闭式切分, 块序列无缝铺满到文件末尾; ModelData / MeshData / BoneData / Material / BoneTrack 出字段 JSON 视图, 其余块出紧凑字段或 hex 摘要 |
| 推进点 | 五个节点包装族的 29 块残差, 以及 `MaterialParamTrack` 子对象类型 |
| 未闭环 | 包装尾区之前多出的可变曲线段无闭式; 容器头 `0x08` 字段语义未定 |
| 细则 | 闭式表与逐族覆盖率见 `docs/notes/named-block.md` |

### CUST 自定义模型 `CUST`

| 项 | 值 |
|:---:|:---|
| 结构 | 外壳明文, 载荷为 16 字节周期异或密文, 解出为标准 FlatBuffers |
| 根表 | `FBSave::CustomModel`, 12 字段, 方块列表在字段 10 |
| 注意 | 文件不含顶点与索引, 几何由 `genGeomTemplate` 按方块列表现算 |
| 推进点 | 接入 FlatBuffers 解析, 输出 JSON |

### 世界区块 `0C 1C 07 06`

## 四、扩展名与内容不符

管线一律按魔数分派, 下列样本按扩展名解码会失败:

| 文件 | 声明扩展名 | 实际魔数 |
|:---|:---:|:---:|
| `res/raw/t1.png` | .png | `ff d8 ff e0`, 实为 JPEG |
| `res/drawable-xxhdpi-v4/ksad_author_icon_tip.webp` | .webp | `89 50 4e 47`, 实为 PNG |
| `res/drawable-xxhdpi-v4/ksad_web_tip_bar_close_button.webp` | .webp | `89 50 4e 47`, 实为 PNG |
| `ui/.../icon_more.png_` | .png_ | `52 49 46 46`, 实为 WebP |

## 五、推进优先级

| 优先级 | 项 | 理由 |
|:---:|:---|:---|
| 1 | KTX 像素解码与 ETC1 编码 | 覆盖 8736 个纹理 372.5 MiB, 全量只有 ETC1_RGB8, 决定美术侧能否直接改图 |
| 2 | 命名区块块写出器 | 容器切块与字段视图已可用, 缺的是按 JSON 改结构再写回的路径 |

| 4 | axml 回写 | 视图已可读, 缺按 XML 重建字符串池与块长度 |
| 5 | 零散容器 (toc / fb / fcm / dat / mp3) | 数量小, 收尾接入 |
