## 二、块头判据

三条判据同时成立的位置才是块头, 缺一不可:

| 判据 | 内容 |
|:---:|:---|
| 类型标识 | 前 2 字节 (u16le) 属于 100 / 101 / 102 / 104 / 105 / 106 |
| 名长 | 第 3 字节为块名长度, 实测 8 至 21, 同一块名在族内长度恒定 |
| 名称 | 其后该长度的 ASCII 串命中 21 个块名的封闭词表 |

判据的用途不是构造块表 (那是定义性动作), 而是给出假拟块头的上界: 全族合法块头的位置
构成一个稀疏集合, 闭式预测落点能落到这些位置上才算命中, 因此落点闭合是非平凡检验。

RibbonEmitterData 的 102 比 101 多 4 字节, BillboardData 的 105 比 104 多 2 字节。

三个逐块族要点:

## 四、切块算法

1. 按块头判据枚举全量候选块头, 命中后跳过块头本身, 避免把名字里的字节当作新块头
2. 块边界由块头枚举直接给出: 每个块头之后的第一个合法块头即该块结束位置, 最后一块以文件末尾结束,
   因此任何合法容器都能无缝铺满到末尾
3. 对每个块头向载荷区开游标, 调用该块名的闭式独立预测载荷长; 闭式只读载荷自身字段, 不读后继块信息
4. 把闭式预测与实测块长比对: 相等记 closed; 不等记 predicted-mismatch 并保留预测与实测的差额;
   该块名没有闭式时记 no-closed-form

每个块带一个边界来源标记:

| 标记 | 含义 |
|:---:|:---|
| closed | 闭式预测的落点等于下一个合法块头或文件末尾 |
| predicted-mismatch | 有闭式但预测长度与实测块长不等, 视图里保留实测与预测的差额 |
| no-closed-form | 该块名没有可用闭式, 或块头之前的字节无法归入任何块, 整段保留为未解析区 |

## 五、字段视图

视图按块名分派, 五个主块族给出字段级 JSON:

| 块族 | 字段 |
|:---:|:---|
| ModelData | 顶层子块数 |
| MeshData | 网格名, 子网格计数, 33 字节扩展区的 hex 摘要与 SHA256 前缀 |
| BoneData | 骨骼名, 标签串, 父骨骼索引 (-1 为树根), 4x4 局部变换矩阵, 可选尾部 u32 |
| Material | 材质名, 类型名 (stdmtl / stdext), 参数条数, 逐条 (类型号, 键名, 值), 条目后残长与其 hex 摘要 |
| BoneTrack | 骨骼名, 骨骼序号, 位置关键帧数, 三段通道的键数与记录数, 记录采样, 文件级尾区的包围盒与挂点表 |

其余块族给出紧凑字段 (例如 SkeletonData 的骨骼数, SubMeshData 的索引数/顶点数/声明号/顶点
步长与顶点缓冲摘要, SkinPatch 的补丁数, EntityData 的路径表, AnimationData 的记录数)。

两块内容不做字段展开, 只保留 hex 摘要: 载荷内超过字段可解释范围的可变区, 以及闭式不闭合的
回退块。摘要形态为 `size` 与 `hex_head` (至多 32 字节) 与 `sha256` (前 16 个十六进制位),
因此视图既能人工阅读, 又不会因为顶点缓冲或像素区而膨胀。

## 七、与逆向文档的口径对照

| 项 | 逆向文档 | 本项目实测 |

| 容器数 | 2098 | 2633 |
| 容器字节 | 134732924 | 248650552 |

容器与区块数翻倍的原因是资源树里同一份 .omod 同时出现在实体目录与 media 下的 omod 副本
目录, 逆向文档的 2098 个文件只统计了其中一份。

块边界的独立真值比对: 与逆向工程产出的块表 blockmap.csv 逐块对齐, 2098 个文件与 50672 个块
的偏移/类型标识/块名/块长四项完全一致, 差异 0 个。该块表按相邻块头之差定义块长, 与本实现的
闭式预测属两条独立路径, 因此这条比对同时验证了切块完备性与块头定位。分族命中数与逆向文档一致或更优: 例如
ParticleEmitterData 2868/2871 与 BillboardData 1455/1474 与 RibbonEmitterData 291/293 与
ParamShapeData 285/287 四项在两侧完全相同。逆向文档里未闭合的 BoneTrack 9 块与
MaterialParamTrack 3 块在本项目已闭合 (前者的文件级尾区按 35 加 8K 解析, 后者按含与不含
63 字节附加区的四条候选判定)。

## 八、未解项

1. 五个节点包装族的 29 块残差: 尾区之前的可变曲线序列多出的一段没有闭式, 目前只能按下一个
   块头回退切分, 具体哪些曲线段被额外写出仍未定位
2. 包装尾区头长度的三种形态 (115 与 119 与 40) 的判定条件: 40 形态的计数在偏移 0, 115 与 119
   形态的计数在偏移 23, 但 111 至 127 之间还有若干档没有取到样本, 目前靠落点判决兜底
3. 容器头偏移 `0x08` 恒为 1 的字段语义: 既不是顶层块数, 也不是流版本, 候选解释都无直接证据
4. 类型标识与 schema 变体的对应关系只有观测 (24 个类型与块名的组合), 未取得引擎侧枚举
5. Material 条目之后 33 字节附加区的语义 (7 个 f32 常成对同值, 尾部 u32 取值 32 至 86),
   以及 33 与 70 两个残长的判定需要读后继网格内容
6. MaterialParamTrack 子对象的类型: 经虚表槽位调用, 需运行时定案; 第 3 块的 63 字节附加区
   目前按候选式覆盖
7. BillboardData 与 RibbonEmitterData 的曲线段个数在载荷内逐数组解析, 个别变体使用 16 字节
   宽的 Vector3 关键帧, 该变体与残差块的关系未定

## 九、复现入口

```bash
cd single-branch/assets

# 契约测试: 合成容器的切块与视图契约, 真实样本的闭合性、JSON 可序列化与逐字节往返
python -m unittest tests.test_named_block -v

# 与逆向块表逐块比对, 原版逆向资料缺失时自动跳过
python -m unittest tests.test_named_block.TestAgainstOriginBlockmap -v
```

逐族覆盖率的口径: 遍历解码工程树里每个命名区块容器, 对 `split_blocks` 给出的块按
`mode` 计数, 闭式闭合记为 closed, 其余计入残差; 块长求和必须等于容器长度减 12,
本文件第六节的两个合计行即该口径的结果。

代码入口: `forge/codecs/named_block.py` 的 `split_blocks` 给出块序列,
`describe` 给出容器视图, `block_fields` 给出单块字段视图, `container_of` 兼容二进制族外壳;
编解码器名为 `named-block`, 视图随解码写入工程树的派生视图目录。
