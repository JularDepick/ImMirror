## 五、ETC1 块布局结论

每块 4x4 像素共 8 字节, 首字放颜色与控制位, 次字放索引:

| 字段 | 位置 | 说明 |
|:---:|:---:|:---|
| 差分标志 | 首位字 bit 33 | 0 为独立模式, 1 为差分模式 |
| 翻转标志 | 首位字 bit 32 | 0 为左右两个子块, 1 为上下两个子块 |
| 基色 1/2 | 首位字 bits 63..40 | 独立模式为两组 4:4:4, 打包顺序 R1 R2 G1 G2 B1 B2 |
| 差分 | 首位字 bits 58..56 等 | 差分模式下每通道 5 位基色加 3 位有符号差 |
| 调制档 1/2 | 首位字 bits 39..37 与 36..34 | 各 3 位, 索引到 8 档幅度对 |
| 像素索引 | 次位字 bits 31..0 | 高低两个 16 位平面, 低位对应子块内第一个像素 |

两条容易踩错的细节:

1. 通道打包是 `R1 R2 G1 G2 B1 B2` 而不是 `R1 G1 B1 R2 G2 B2`,
   按后者解出来的图像在块边界处完全断裂;
2. 索引档位要先经过置乱表 `(2, 3, 1, 0)`, 且子块内遍历是列优先,
   翻转模式下每个子块沿列方向跨 2 个索引位推进。

调制幅度八档为 `(2,8) (5,17) (9,29) (13,42) (18,60) (24,80) (33,106) (47,183)`,
档内 4 个幅度顺序为大幅负、小幅负、小幅正、大幅正。

## 六、解码正确性验证

验证不看肉眼, 用两条与内容无关的量化判据:

| 判据 | 定义 | 正确布局 | 错误布局 |
|:---:|:---|:---:|:---:|
| mip 一致性 | 0 级 2x2 盒式降采样与 1 级的平均绝对差 | 1.90 | 8.10 (遍历顺序错) / 48.25 (通道打包错) |
| 图像总变差 | 相邻像素平均绝对差, 越小说明越连贯 | 4.23 | 9.54 (遍历顺序错) / 20.7 (通道打包错) |

两条判据在 12 张真实纹理上取均值, 覆盖 64x64 到 1280x720 的尺寸。
mip 一致性能到 1.9 说明连低层 mip 都能与上层对上, 通道、通道量级、块序都不可能再错位。

## 七、工程文件与直通契约

| 项 | 值 |
|:---:|:---|
| 工程文件 | `project/<原相对路径>`, 内容就是裸 KTX 字节, 逐字节直通 |
| PNG 旁挂 | `project/_png/<原相对路径去掉 .ktx>.png`, 8 位 RGBA, 0 级 mip 像素 |
| 索引记录 | `side_files` 字段登记 PNG 相对路径, 不改 `source_sha256` |
| 未支持格式 | 不产出 PNG, `meta.pixel_codec` 为 null, 其余字段照常 |

`encode(decode(x)) == x` 由直通保证: 编解码器只搬运原始字节, 像素解码结果不参与编码。
带容器的素材由二进制族编解码器负责套壳, 旁挂 PNG 走同一套逻辑, 因此
`assets/entity/*.ktx` 与 `media/ktx/*.ktx` 都会产出 PNG。

## 八、PNG 回写

`forge.ktx_png import` 以 PNG 为准重建 KTX, 规则如下:

1. PNG 像素与当前 KTX 解码结果逐像素相同: 直接保留原 KTX 字节, 不动文件;
2. 有改动: 重压 0 级像素, 低层 mip 由 0 级逐级 2x2 盒式降采样重算后再压;
   头部 13 个字段与键值区沿用原文件, 各级 mip 的长度字段按新数据重算;
3. 写回一律写裸 KTX, 套容器交给 `forge pack`。

不保证逐字节一致的原因有两条, 都写进文档以免误判:

- ETC1 的块编码是多解的, 同一个 4x4 像素块存在大量不同的字节能解出同样的像素;
- 低层 mip 在原始文件里未必是对 0 级做盒式降采样的结果, 回写时统一重算。

像素级自检 (`forge.ktx_png check`, 28 张真实纹理抽样):

| 指标 | 值 |
|:---:|:---|
| 逐字节相同 | 0 / 28 (设计如此) |
| 字节长度相同 | 28 / 28 |
| 平均绝对误差 | 均值 0.91, 最大 2.53 |
| 单像素单通道最大差 | 均值 86.6, 最大 153 |

平均误差不到 1 个色阶, 说明整体像素几乎无损; 单像素最大差出现在强边缘块,
是 ETC1 每半块只有一个基色的量化极限, 不是实现错误。自检的判据以平均误差为主
(阈值 6.0), 单像素最大差只做灾难性错误兜底 (阈值 200)。

## 九、命令

```bash
python -m forge.ktx_png stats    --root ../client/temp/original/fake-mini-BUT-true-moments/src
python -m forge.ktx_png export   --root <资源树> --out <工程树> [--limit 数量]
python -m forge.ktx_png import   --project <工程树> [--limit 数量]
python -m forge.ktx_png check    --project <工程树> [--limit 数量]
```

`forge unpack` 会自动产出 PNG 旁挂, 不需要单独跑一次 export。
