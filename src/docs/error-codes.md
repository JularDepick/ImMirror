# 错误码对照表

> 本文档覆盖 `/api/v1` 下全部接口的错误响应。
> 响应包络固定为: 成功 `{ "ok": true, "data": ... }`, 失败 `{ "ok": false, "error": { "code": "...", "message": "..." } }`。
> 客户端必须以 `error.code` 分支处理, `error.message` 只用于日志与兜底展示, 不作为判断依据。

## 一、错误码总表

| 错误码 | HTTP 状态 | 触发场景 | 客户端建议处理 | 面向用户的中文提示 |
|:---:|:---:|:---|:---|:---|
| `BAD_REQUEST` | 400 | 请求体不是合法 JSON 或不是 `application/json`; 字段缺失或格式非法 (邮箱格式, 验证码位数, 登录标识符为空); 密码长度不在允许区间; 换绑时新邮箱与当前邮箱相同 | 按 `message` 定位具体字段并修正后重试, 不要原样重发; 属于客户端参数问题, 建议记录一条埋点 | 填写的信息不完整或格式不对, 请检查后重试 |
| `AUTH_INVALID_IDENTIFIER` | 400 | 登录时 `identifier` 既不含 `@` 也不是纯数字 | 输入框本地先做格式判定, 占位文案提示"邮箱或 9 位 UID"; 服务端返回时聚焦到账号输入框 | 请填写邮箱或 9 位数字 UID |
| `AUTH_INVALID_CREDENTIALS` | 401 | 密码错误; 账号不存在 (含 UID 不存在, 出于枚举防护与密码错误同码); 验证码登录通过但账号不存在; 换绑邮箱时密码不匹配 | 允许重新输入, 但连续失败会升级为 `RATE_LIMITED`; 同时展示"用验证码登录"与"忘记密码"入口 | 账号或密码不正确, 也可以改用验证码登录 |
| `AUTH_CODE_INVALID` | 400 | 验证码不存在, 填写错误, 已被使用; 重置密码时验证码有效但账号不存在 | 允许重新填写, 每次校验都会消耗一次尝试次数; 连续错误达到上限会转为 `AUTH_CODE_ATTEMPTS_EXCEEDED` | 验证码不正确, 请重新输入 |
| `AUTH_CODE_EXPIRED` | 400 | 验证码超过 `CODE_TTL_SECONDS` (默认 600 秒) | 引导重新获取验证码, 发送按钮需遵守 `SEND_COOLDOWN_SECONDS` 冷却 | 验证码已过期, 请重新获取 |
| `AUTH_CODE_ATTEMPTS_EXCEEDED` | 429 | 单条验证码校验次数达到 `VERIFY_MAX_ATTEMPTS` (默认 5) | 当前验证码作废, 必须重新获取; 输入框保留但清空内容, 发送按钮进入冷却 | 验证码错误次数过多, 请重新获取验证码 |
| `AUTH_EMAIL_TAKEN` | 409 | 注册时邮箱已注册 (验证码校验通过后才会返回); 换绑邮箱时新邮箱已被其他账号占用 | 注册流程引导"直接登录"与"忘记密码"; 换绑流程提示更换邮箱, 不关闭弹窗 | 该邮箱已被使用, 请更换邮箱或直接登录 |
| `AUTH_UNAUTHORIZED` | 401 | 缺少 `Authorization` 头, 或格式不是 `Bearer <token>`; 令牌不存在; 令牌已被登出撤销; 令牌归属账号不存在 | 清理本地令牌并跳转登录页, 不要循环重试; 若本机并无令牌则视为客户端状态异常 | 登录状态已失效, 请重新登录 |
| `AUTH_SESSION_EXPIRED` | 401 | 会话超过有效期 (默认 30 天) 未被使用 | 与 `AUTH_UNAUTHORIZED` 相同的重新登录流程; 建议先尝试一次静默校验再跳转 | 登录已过期, 请重新登录 |
| `RATE_LIMITED` | 429 | 验证码发送冷却中; 同一邮箱当日发送达上限; 同一 IP 每小时发送达上限; 同一邮箱每小时重置密码达上限; 登录连续失败触发指数退避; 同一 IP 每分钟请求总量达上限 | 展示剩余等待秒数, 到时间后自动恢复按钮; 禁止无限自动重试, 建议指数退避并提示用户 | 操作太频繁了, 请稍后再试 |
| `WALLET_ALREADY_CHECKED_IN` | 409 | 当日 (Asia/Shanghai 自然日) 已完成签到 | 不弹错误框, 直接把界面切到"已签到"状态并刷新余额与进度 | 今天已经签到过啦, 明天再来 |
| `NOT_FOUND` | 404 | 路径不存在或方法与路径不匹配 | 检查路径拼写与 `/api/v1` 前缀; 若为客户端内置路径, 视为客户端版本过旧 | 接口不存在, 请升级到最新版本 |
| `INTERNAL` | 500 | 未捕获异常; UID 分配连续冲突导致的兜底失败 | 可退避重试一次, 仍失败则提示稍后再试; 上报服务端日志与请求时间 | 服务开小差了, 请稍后再试 |

## 二、使用约定

1. 所有响应都是 JSON, 任意路径都不会返回 HTML; 因此客户端可以统一按 JSON 反序列化, 解析失败即视为异常网络响应
2. 未认证接口收到 401 说明令牌问题, 已认证接口收到 401 说明令牌失效或缺失, 客户端处理方式一致
3. 400 与 409 属于可修正的业务失败, 429 属于节流失败, 500 属于服务端失败; 只有 500 与网络错误适合自动重试
4. 同一错误码在不同接口的含义保持一致, 不要在客户端按"接口 + 错误码"做二次映射
5. 服务端不返回堆栈与内部细节, `message` 可能与本文档的文案略有差异, 以 `code` 为准
