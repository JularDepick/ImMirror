# 会话与令牌策略

> 本文档描述服务端当前实际实现, 与代码行为一致; 修改实现时请同步更新本文档。

## 一、令牌形态

| 项 | 值 |
|:---:|:---|
| 生成方式 | 32 字节安全随机数, 十六进制编码后为 64 个字符 |
| 明文去向 | 只出现在签发响应中, 服务端不保存明文 |
| 服务端存储 | 只保存明文的 SHA-256 摘要, 摘要列唯一 |
| 传输方式 | 请求头 `Authorization: Bearer <token>` |
| 有效期基准 | `SESSION_TTL_DAYS` 天, 默认 30 天 |
| 关联主体 | 会话绑定账号主键, 不绑定邮箱; 换绑邮箱不影响已有会话 |

## 二、签发时机

以下接口成功后会新建一条会话, 响应里返回 `uid` `email` `token` `expiresAt`:

| 接口 | 触发条件 |
|:---|:---|
| `POST /api/v1/auth/register` | 邮箱验证码与密码校验通过, 账号创建成功 |
| `POST /api/v1/auth/login` | 邮箱或 UID 加密码校验通过 |
| `POST /api/v1/auth/login/code/verify` | 邮箱验证码校验通过且账号存在 |

`expiresAt` 为 Unix 毫秒时间戳, 等于签发时刻加完整有效期。

## 三、客户端保存建议

1. 令牌属于长期凭证, 建议存于受系统保护的存储 (安卓侧使用加密存储, 不要在日志与崩溃上报中输出)
2. 只保存令牌与 `uid`, 不要保存密码; 邮箱仅作界面展示与回填
3. 收到 401 时立即清除本地令牌, 避免继续用失效令牌刷接口
4. 同一次登录会话内不要自行并行刷新令牌, 服务端不支持刷新令牌接口, 续期由鉴权请求自动完成

## 四、滑动续期

| 项 | 说明 |
|:---:|:---|
| 触发点 | 任何带 `Bearer` 令牌且鉴权成功的请求, 例如 `GET /api/v1/me` `GET /api/v1/wallet` `POST /api/v1/wallet/checkin` `POST /api/v1/auth/logout` |
| 判定条件 | 会话记录的 `expires_at` 早于"当前时刻加完整有效期"时执行续期 |
| 续期结果 | 把 `expires_at` 写为当前时刻加完整有效期, 令牌本身不变 |
| 实现细节 | 续期后下一次鉴权仍满足判定条件, 因此实际上每次鉴权成功都会刷新一次过期时间; 这是有意为之的"活跃即保活"策略 |
| 返回值 | 续期只体现在会话记录上, 鉴权类接口不返回新的 `expiresAt`; 客户端不要以本地时间推算过期, 一律以 401 响应为准 |

结论: 只要账号在 30 天内至少成功调用一次需要鉴权的接口, 登录状态就会一直保持。

## 五、失效与重新登录判定

| 失效原因 | 服务端表现 | 客户端判定 |
|:---|:---|:---|
| 超过有效期未使用 | 401 `AUTH_SESSION_EXPIRED` | 清除令牌, 跳转登录页 |
| 主动登出 | 该会话写入撤销时间, 之后返回 401 `AUTH_UNAUTHORIZED` | 清除令牌, 正常回到登录页, 无需提示错误 |
| 忘记密码重置成功 | 该账号全部会话被撤销, 旧令牌返回 401 `AUTH_UNAUTHORIZED` | 清除令牌, 提示"密码已重置, 请重新登录" |
| 令牌被伪造或不存在 | 401 `AUTH_UNAUTHORIZED` | 清除令牌, 视为登录态异常 |
| 令牌所属账号被删除 | 401 `AUTH_UNAUTHORIZED` | 清除令牌, 回到登录页 |

重新登录判定: 只要收到 401, 无论 `AUTH_SESSION_EXPIRED` 还是 `AUTH_UNAUTHORIZED`, 都进入同一套"清理令牌 -> 回到登录界面"流程; 唯一例外是登出接口本身返回 401, 说明令牌已失效, 直接回到登录界面即可。

## 六、多端登录

| 问题 | 当前实现 |
|:---:|:---|
| 多端是否互斥 | 不互斥。每次登录, 注册, 验证码登录都会新建独立会话, 同一账号可同时存在多条有效会话 |
| 登出影响范围 | 只撤销当前请求携带的那条会话, 其他设备保持在线 |
| 重置密码影响范围 | 撤销该账号全部会话, 所有设备都需要重新登录 |
| 换绑邮箱影响范围 | 不影响会话, 已有登录状态继续可用, 账号标识 `uid` 不变 |
| 会话数量上限 | 当前实现未设置上限, 也没有"在线设备列表"接口 |

若后续需要强制单端在线, 应在服务层签发新会话时撤销该账号的旧会话, 并同步更新本文档。

## 七、审计字段

会话表记录以下字段, 用于排查"为什么掉线"与异常登录分析:

| 字段 | 含义 |
|:---:|:---|
| `ip` | 签发时的客户端地址, 反向代理下取 `X-Forwarded-For` 首选地址 |
| `ua` | 签发时的 `User-Agent`, 最长保留 255 个字符 |
| `created_at` | 签发时间, Unix 毫秒 |
| `expires_at` | 当前有效期, 会随滑动续期变化 |
| `revoked_at` | 撤销时间, 为空表示仍有效 |

服务端不记录令牌明文, 因此日志与数据库中都无法还原已签发的令牌。

## 八、相关配置

| 键 | 默认 | 影响 |
|:---:|:---:|:---|
| `SESSION_TTL_DAYS` | 30 | 会话有效期, 修改后对已签发会话在下一次鉴权时生效 |
| `REQUEST_MINUTE_IP_LIMIT` | 120 | 鉴权请求同样计入单 IP 每分钟上限, 高频轮询会被限流 |
